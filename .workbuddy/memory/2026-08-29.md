### 关键手法
- **接口返回体契约测试不启 Spring 容器、不连库**：`MockMvcBuilders.standaloneSetup(...)` + `setConversionService` + `setMessageConverters(appObjectMapper)` + `setControllerAdvice(new GlobalExceptionHandler())`，即可完整覆盖「参数绑定 → Jackson 序列化」这段决定返回值的链路，单次运行 <2s。
- 全局 jackson 配了 `SNAKE_CASE`，**请求体也要用 snake_case**（`datasource_name`/`datasource_type`），写 camelCase 会 400；`Result` 的 `code/message/data` 不受影响。
- JUnit `@ParameterizedTest` 对 enum 参数走 `Enum.valueOf`，**必须传大写枚举名**，传 code 会 ParameterResolution 失败。

### 定位到的真实回归（已修复 2 处）
1. **非法 `storageEngine` 静默降级为「不过滤引擎」**（严重）
   - 合并前该参数由 `Enum.valueOf` 绑定，非法值直接失败；合并后走 `StringToDatasourceTypeConverter`，`DatasourceType.fromCode()` 对未知值返回 `null`，导致 `GET /metadata/table/columns?storageEngine=nope` 变成「只按库+表查」，把其它引擎的同名列一起返回。
   - 修复：`StringToDatasourceTypeConverter` 对非空且无法识别的取值抛 `IllegalArgumentException`；`GlobalExceptionHandler` 新增 `MethodArgumentTypeMismatchException` 处理器返回 400（此前落到 `Exception` 兜底分支返回 500）。
2. **`storage_engine` 落库值由枚举名变为 code，历史数据读不出来**
   - 合并前 `StorageEngineType` 无 `@EnumValue`，MyBatis 默认 `EnumTypeHandler` 落库**枚举名**（`MYSQL`）；合并后 `DatasourceType` 的 code 上有 `@EnumValue`，MyBatis-Plus 改走 `MybatisEnumTypeHandler` 落库**小写 code**（`mysql`）。
   - 结果：未迁移的历史行读回来是 `null`（不报错，但引擎过滤整体失效）。迁移脚本已放在 `src/main/resources/sql/migrate/20260826-storage-engine-enum-name-to-code.sql`（`LOWER(storage_engine)`，幂等）。**生产环境需执行一次。**
   - 测试里用 `legacyUppercaseRowsLostBeforeMigration` 明确记录了这个现状，`legacyUppercaseRowsReadableAfterMigration` 验证迁移有效。
