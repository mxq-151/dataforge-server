### 3. 契约事实修正（关键，易踩）

`ContractMockMvcSupport` 原只有一组按 `application.yml` 语义（**SNAKE_CASE + NON_NULL**）手工构造的
ObjectMapper。但 README 注意事项 4 明确：yml 的 `property-naming-strategy: SNAKE_CASE`
被 `WebMvcConfig` 的 `@Primary ObjectMapper` 覆盖，**线上是 camelCase**。
按旧一组写契约测试会断言出线上并不存在的字段名，产出"假绿"。

→ 新增 `productionObjectMapper()` / `productionMockMvc()`（直接复用 `new WebMvcConfig().objectMapper()`），
类注释写明两者取舍与适用场景。历史两个契约测试（`MetadataApiContractTest`、`DatasourceApiContractTest`）
仍在用旧一组（断言 snake_case），**待确认后迁移**。

### 4. `GlobalExceptionHandler` 补精确处理器（此前都被 `Exception` 兜底吞成 500）

- `MissingServletRequestParameterException` → 400「缺少必填参数: X」
- `NoHandlerFoundException` / `NoResourceFoundException` → 404
- `HttpRequestMethodNotSupportedException` → 405

动机与文件内既有的 `MethodArgumentTypeMismatchException` 500→400 完全一致：**客户端错误不应报成服务端故障**
（前端会提示"服务器内部错误,请联系管理员"）。资产契约测试的「未映射路径应为 404」一例正是抓到这点才失败。
