### R4 权限（本轮改动最大）

- **语义变更 — 行/列权限合并改为「交集收紧」**（`common/security/DataAccessPermissionService`）
  - `getMergedRowFilterSql`：不再「任一命中权限未配行过滤即整体放宽」，改为把所有已配置的过滤条件 AND；
    全部未配置才返回 null。
  - `getAllowedColumns`：不再「任一未限制即放宽 + 其余取并集」，改为对**配置了列白名单的权限取交集**；
    返回的列名统一小写。交集为空 → 返回空集合（不授权任何列），而不是 null。
  - `getMergedTablePermission`：脱敏规则由「后一条覆盖前一条」改为按列合并、同列取更严格规则
    （full > idcard/phone > email > partial），避免宽权限静默覆盖窄权限的脱敏。
- **fail-close + 覆盖缺口修复**（`AbstractBaseExecutionStrategy`）
  - 按分号拆语句**逐条**校验（新工具 `common/sql/SqlScriptSplitter`）。旧实现把整段脚本交给
    JSqlParser，多语句必解析失败 → 整段放行，是一条绕过点。
  - 以 DML 关键字开头但解析失败的语句 → **默认拒绝**（原来只打 debug 日志后放行）；
    权限判定过程异常同样默认拒绝。
  - Calcite 认不出但以 DDL 关键字（CREATE/ALTER/DROP/TRUNCATE/RENAME/COMMENT/GRANT/REVOKE/ANALYZE）
    开头的语句，非 ops/管理员默认拒绝。
  - 非 SQL 代码类型（Scala/Python/Jar）跳过 SQL 语句级校验，避免 `select = {}` 这类标识符误判。
  - 表引用收集改用新工具 `common/sql/SqlTableCollector`：覆盖 JOIN 右侧、派生表、WHERE/HAVING/ON/
    投影列子查询、UNION 分支、CTE。**旧实现用 `SubJoin`/`SubSelect` 反射，而 JSqlParser 4.9 已改名为
    `ParenthesedFromItem`/`ParenthesedSelect`，导致 JOIN 的表与子查询里的表完全漏检**（真实漏洞，已修）。
- **下发前 SQL 改写**（新类 `SqlPermissionRewriter`，在基类 `checkPermission` 末尾统一调用
  `applyRowColumnRewrite`，所有 SQL 路径生效）
  - 行过滤 → AND 进 WHERE（多表时先用别名限定条件列；该层存在外连接则拒绝，因为注入会改变连接语义）；
    列白名单 → 把 `SELECT *` 展开/投影列裁剪为白名单；只允许单表顶层查询做列裁剪（集合运算分支/子查询里
    裁剪会改变外层列集合 → 拒绝）。
  - 改写结果写 `CodeExecutionContext.effectiveCodeContent`，实际下发用 `getExecutionCodeContent()`；
    日志/审计/回显仍用原始 `codeContent`。Spark/Flink/HBase/JDBC/Kyuubi 的取内容处已全部切到该 getter。
  - **JSqlParser 的宽松解析陷阱**：`parseCondExpression("region =")` 会静默返回裸列 `region`，
    注入后等价于把限制放宽。已加「往返一致性校验」（解析结果重新序列化后做去空白/去大小写比较，
    不一致即拒绝）。`SqlPermissionRewriterTest.acceptsCommonRowFilterForms` 守住不能误伤合法写法。
  - 行过滤已注入时，`applyRowFilterAndMasking` **跳过结果集二次过滤**（多表下后过滤只取第一张表的
    条件，重复过滤会裁错），脱敏与列裁剪照旧执行。
  - 顺带闭合聚合泄露：`count/sum` 的口径现在也被行级权限限定。

### R1 元数据

- **同步失败升级为可观测告警**（新类 `metadata/service/MetadataSyncAlertService`）
  - DDL 后同步失败 / RENAME 失败 / 全量同步失败 → 写审计日志
    （`module=metadata`、`operation=METADATA_SYNC_FAILED` / `METADATA_FULL_SYNC_FAILED`、`response_status=500`）
    + 固定前缀 `[METADATA-SYNC-ALERT]` 的 ERROR 日志。
  - 告警写入点刻意放在**事务外**（`AbstractBaseExecutionStrategy.handleDdlMetadataSync`、
    `DatasourceConfigController.syncMetadata`）：`MetadataSyncService` 的方法带 `@Transactional`，
    且内层异常可能把外层事务标记 rollback-only，写在里面会被回滚吞掉。
  - 告警自身异常必须吞掉，不能影响 DDL 结果（有单测覆盖）。
- **未标注表/字段清单**：`GET /metadata/annotation-gaps?datasourceId=&databaseName=&limit=`
  （新类 `MetadataAnnotationGapService` + 3 个 VO）。只列出有缺失的表，表注释缺失与字段注释缺失分别计数，
  按调用者的库/表权限过滤（口径对齐 `/metadata/tables`）。用 MyBatis-Plus wrapper 实现，避免新增 4 套方言 XML。
- README 补了「数据访问权限模型（务必先读）」：明确**租户不是数据隔离边界**（租户与用户 1:1，资源表无租户字段）
  —— 这是 R4④ 要求写清的产品说明。
