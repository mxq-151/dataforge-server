# 数据大小增长率：天分区表 vs 全量表 双口径改造

## Context（为什么改）

现状 `AssetInventoryService.sizeGrowth()`（[AssetInventoryService.java](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/java/com/bigdata/modules/asset/service/AssetInventoryService.java#L474-L561)）对**所有表**都用同一套口径：拿 `asset_catalog_daily` 里「最新快照的表级 `size_bytes`」对比「30 天前的表级 `size_bytes`」。

这对**天分区表**是错的：分区表整表大小天然只增不减（按天追加分区），整表对比永远显示「增长」，看不出「某一天分区异常膨胀」这一真正要抓的突增。而对**全量表**（覆盖写），整表大小每天被快照记录，本就是合适口径。

**目标**：按用户口径分流
- **天分区表**：按「近几天的分区大小」计算 —— 取该表最新分区大小，对比近 N 天分区均值。
- **全量表**：沿用每日 `asset_catalog_daily.size_bytes`，对比近 N 天快照均值。

已确认的决策：
1. 天分区表判定 = `table_metadata.partition_columns` 非空且含日期类分区列（`dt/ds/date/day/pt/...`）。
2. 对比基准 = **近 N 天均值**（N 默认 7，可调）。
3. 分区大小采集覆盖引擎：MySQL/MariaDB、PostgreSQL、Doris/StarRocks、ClickHouse、Hive（经 Kyuubi）。未实现/取不到者静默跳过。
4. 落库 = **新增分区日表，存该表「当日最新分区」**，保留 180 天。

## 设计要点

### 1. 新增分区日表 `table_partition_size_daily`

一行 = 一张天分区表 × 一个统计日，记录「当日最新分区」的值与大小。累积多天后即可算「近 N 天分区均值」。

字段（对齐 `asset_catalog_daily`/`scheduler_task_run_daily` 风格）：
`id`(PK auto)、`stat_date`、`table_metadata_id`、`datasource_id`、`database_name`、`table_name`、
`partition_column`、`partition_value`、`size_bytes`、`row_count`、`create_time`、`update_time`；
唯一键 `uk_partition_size_daily(stat_date, table_metadata_id)`，索引 `stat_date` / `table_metadata_id`。

四套方言初始化 SQL 同步追加（[dataforge-mysql.sql](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/resources/sql/init/dataforge-mysql.sql)、mariadb、postgresql、h2），差异照抄 `asset_catalog_daily`：
MySQL/MariaDB 内联 `COMMENT` + `ENGINE=InnoDB`；PG `BIGSERIAL/SMALLINT/INTEGER/DATE/TIMESTAMP` + `COMMENT ON`；H2 `BIGINT AUTO_INCREMENT` + `CREATE UNIQUE INDEX` + `COMMENT ON`。

### 2. 天分区表判定（复用，不新增第二套口径）

新增工具类 `DailyPartitionDetector`（asset 模块）：解析 `partition_columns`（逗号分隔或 JSON，兼容 `AssetCatalogService.parsePartitionColumns` 的两种形态），任一列名归一化后命中日期类集合即判定为天分区表。
日期类集合：`dt, ds, date, day, pt, stat_date, data_date, log_date, partition_date`，并匹配后缀 `*_date / *_dt / *_day / *_ds`；对含日期函数的表达式（如 `toYYYYMM(dt)`、`to_days(...)`）取其中的列名再判。

### 3. 分区大小采集（唯一新增的引擎能力）

在 [ExecutionStrategy.java](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/java/com/bigdata/modules/development/service/execution/ExecutionStrategy.java) 增加默认方法（默认返回空 Map，未实现引擎自动跳过）：

```java
record TablePartitionSize(String partitionValue, Long sizeBytes) {}
default Map<String, TablePartitionSize> listLatestPartitions(
        DatasourceConfig cfg, String databaseName, Collection<String> tableNames) { return Map.of(); }
```

- [AbstractJdbcExecutionStrategy.java](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/java/com/bigdata/modules/development/service/execution/AbstractJdbcExecutionStrategy.java#L333-L346) 委托给 `JdbcTableStatsCollector` 新增方法，按真实引擎分支：
  - MySQL/MariaDB：`information_schema.PARTITIONS`（`PARTITION_NAME`、`PARTITION_DESCRIPTION`、`DATA_LENGTH+INDEX_LENGTH`）取每个表最大分区。
  - PostgreSQL：`pg_inherits` + `pg_total_relation_size` + `pg_get_expr(relpartbound)` 解析分区值，取最大子分区。
  - ClickHouse：`system.parts` 按 `partition` 聚合 `sum(bytes_on_disk)`，取最大分区。
  - Doris/StarRocks：逐表 `SHOW PARTITIONS FROM db.tbl`，从结果中取大小列（列名按版本兼容，取不到即跳过该表）。
- [KyuubiExecutionStrategy.java](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/java/com/bigdata/modules/development/service/execution/KyuubiExecutionStrategy.java#L1087-L1121) 实现 Hive：`SHOW PARTITIONS db.tbl` 取最大分区值，再对该分区取大小（`DESCRIBE EXTENDED db.tbl PARTITION(...)` 的 `totalSize`，取不到即跳过）。
- 全部失败只记 warn、返回已采集部分（与 `listTableSizes` 同策略），不影响存量与其它功能。

### 4. 采集服务与任务（asset 模块，与读取方同域）

- `entity/AssetPartitionSizeDaily.java`（`@TableName`，继承 `BaseEntity`）+ `mapper/AssetPartitionSizeDailyMapper.java`（仅 `extends BaseMapper`，无 XML，照抄 `AssetCatalogDailyMapper`）。
- `service/AssetPartitionSizeCollectService.java`：
  - `collect(LocalDate statDate)`：取全部 `TableMetadata`（`id, datasource_id, database_name, table_name, partition_columns`）→ 用 `DailyPartitionDetector` 过滤出天分区表 → 按数据源分组，`ExecutionStrategyFactory.getStrategy(config)` 调 `listLatestPartitions` → 先按 `stat_date` 删旧、再逐条 insert（幂等覆盖写，照抄 `AssetCatalogSnapshotService.snapshot`）；返回摘要 record。
  - `purgeBefore(cutoff)`：保留 180 天（照抄 `purgeBefore`）。
  - `latestWindow(tableMetadataId, statDate, days)`：读取该表近 N 条记录，供 size-growth 使用。
- `task/AssetPartitionSizeCollectTask.java`：`@Scheduled(cron = "0 20 2 * * ?")`（02:20，排在 02:15 存储大小刷新之后、02:30 目录快照之前），`runOnce(LocalDate)` 双入口，整包 try/catch（照抄 [AssetCatalogSnapshotTask.java](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/java/com/bigdata/modules/asset/task/AssetCatalogSnapshotTask.java)）。
- [AssetCatalogController.java](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/java/com/bigdata/modules/asset/controller/AssetCatalogController.java#L273-L278) 增手动触发 `POST /asset/task/partition-size/run?statDate=yyyy-MM-dd`（`SUPER_ADMIN`，默认昨天，照抄既有 task/run 接口）。

### 5. 改造 `sizeGrowth()` 为双分支

入参增加可选 `windowDays`（默认 7，夹到 2~30；未传保持向后兼容）。

- 载入最新快照当日可见行；一次性载入 `table_metadata` 的 `id → partition_columns` 投影（复用 `envProject` 的投影查询方式），据此把表分成「天分区表 / 其余（全量表）」。
- **全量表分支**：`current` = 最新快照 `size_bytes`；`baseline` = 该表在窗口内更早各日快照 `size_bytes` 的均值；`growthRate = (current - baseline)/baseline`。历史不足（窗口内记录 < 2）跳过。
- **天分区表分支**：从 `table_partition_size_daily` 取该表窗口内记录；`current` = 最新记录 `size_bytes`；`baseline` = 更早记录的 `size_bytes` 均值；`growthRate` 同上。记录 < 2 跳过（不退回整表口径 —— 分区表整表口径无意义，宁可暂不显示）。
- 两分支统一按 `current > minSizeBytes` 且 `growthRate*100 > growthPercent` 过滤，合并后按 `growthRate` 降序。
- [AssetSizeGrowthVO.java](file:///Users/mxq/Desktop/dataforge-docker/dataforge-server/src/main/java/com/bigdata/modules/asset/vo/AssetSizeGrowthVO.java) 新增只读字段 `tableType`(`PARTITIONED`/`FULL`)、`compareDays`、`partitionValue`（前端结构化类型，多余字段静默忽略，向后兼容；前端要展示时另开改动）。
- 环境/项目/权限口径不变（沿用 `DeployEnvParser`、`AssetPermissionSupport`、`projectByDatasource`）。

> 注：前端消费方在独立目录 `/Users/mxq/Desktop/dataforge-docker/dataforge`（`AssetOverviewTab.tsx` 的 `SizeGrowthSection`）。本次仅后端；新增字段不破坏现有渲染，如需展示表类型/对比周期再单独提前端改动。
